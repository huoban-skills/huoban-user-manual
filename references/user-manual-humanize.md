# 手册表述规范

手册正文怎么措辞、怎么断句、哪些说法不许出现，都按本文件执行；口吻全册一致、稳定不带个人风格。写稿时对照，自检时复查。本文件是表述层的唯一事实源，writing-guide 只管结构和内容。

## 一、克制与口吻

1. **口吻总纲：成熟 SaaS 产品的官方帮助中心**。中性、直接、克制，跟读者平视，用业务语言，但不闲聊、不说书。准确先于修辞，清晰先于热闹，不追求生动。
2. **禁比喻、拟人、夸张**。"撑起销售侧""把动向摊开了""这笔生意开不了头""特殊地位"这类修辞不进手册。后果句平铺直叙，点名办不成的单据即止，不渲染：
   - ❌"客户没建，这笔生意在系统里根本开不了头" ✅"客户没建，报价单和销售订单的客户栏就填不上，单据无法创建"。
3. **压缩不牺牲语法**。短句必须仍是完整的自然中文句，主语谓语齐全，不写电报句、口号句：
   - ❌"导入依赖关联资料先就位。" ✅"导入前，被关联的资料要先建好。"
4. **实现视角不落笔**。系统行为只写读者可见的结果，不写它是怎么实现的："写死在计算里""口径""逻辑""字段引用""由单据驱动"这类配置侧措辞不进使用手册（"驱动"已入机检行话表）：
   - ❌"这个口径写死在计算里，系统给这条数据加了保护" ✅"不良品仓由系统预置，不能改名，也不能删除"。
5. **同一句式全册限频**。"无从谈起""无从下手""就都 X 不了"这种带风格的非 UI 句式，全册最多出现 2 次；第三次换成平实说法或直接删掉。

## 二、用词

6. **禁止技术术语**（validator、trigger、automation、config、API 等）："数据触发自动xxx"→"系统会自动xxx"；"validator 校验"→"保存时系统会自动检查，xxx时弹窗提示"。
7. **不说"记录"，说具体的表单数据**：✅"保存后生成一条入库单" ❌"保存后生成一条记录"（机检兜底「条记录」；「收款记录」这类页签原名不受影响）。泛指时说「一条数据」：✅"同一个产品放在三个仓，库存表里就会有三条数据"。读者认识的是单据和资料，不是"记录"。
8. **界面名词用平台/系统原名**，不转述不生造。字段名、按钮名以采集到的系统原词为准，凭印象写会让读者按图索骥找不到；`render.py --vocab` 拿词表逐个核对，报出来的逐条确认是举例值还是写错了。
9. **用读者嘴里的词**。判据：一线业务人员口头会不会这么说。名词写完拿这个判据过一遍，读者口头不会说的换成白话；拿不准读者懂不懂的词，宁可多用几个字把意思摊开。
10. **指代补全**。主语写具体角色（销售、采购、仓管、财务）或具体的物（货、钱、单据）；「你」只指正在操作的那个人，公司层面的往来写「公司」：
    - ❌"你买进卖出的每一样东西，这张表里都要有一条" ✅"销售下单卖的、采购下单买的每一样东西，这张表里都要存一条数据"。
    - ❌"客户那边算的是别人欠你多少" ✅"客户那边算的是别人欠公司多少"。
11. **概括用界面原名列举，不自造归类词**。拼出来的词看着像业务词，界面上找不到、一线嘴里也没有，读者对不上号（判据同第 9 条）：
    - ❌"表单下拉里的各种选项和类型" ✅"填单时下拉里选的内容（客户来源、结算方式、省市这些）"。

## 三、复读与模板

12. **固定位置不复用措辞**。章开场、节首句、步骤收尾这些结构位置每章都有，但措辞不许跨章盖章。
    - ❌ 五章开场都是"X 是…的档案表"；三节首句都以"按下面步骤建档"收尾；四章都用"保存后列表里出现这个 X，开单时就能选到它了"收步。
    - ✅ 同类信息换角度说：这章可以讲建好后谁用它，下章讲多久建一次、由谁维护。换角度只换信息角度，不升级修辞，口吻仍受第一节约束。
    - 字面 UI 指令不算复读："点右上角的「创建」"界面长什么样就写什么，五章一样是对的。
    - 常见问题固定"原因 → 解决办法"的结构不算复读：结构可以同，措辞要贴各自的问题。
    - 机检兜底：同一子句（去掉「」里的界面名后）出现 3 次以上会报错。
13. **例句不是标准答案**。写作规范里的括号例句只示意结构，措辞不得照抄；"按下面步骤""取数的档案"这类例句片段已进机检黑名单。
14. **标题不复读**。标题下第一句不复述标题；常见问题的答案不重抄问题。

## 四、陈词与套路句

15. **陈词黑名单**（机检兜底）：旨在、致力于、助力、赋能、极大提升、高效便捷、一目了然、轻松实现、值得注意的是、总而言之、综上所述、众所周知。价值用具体业务结果说：✅"少录一遍数据" ❌"大幅提升录入效率"。
16. **动词直给**。是就写"是"，有就写"有"，不绕"作为…承担着…的角色""扮演…角色"（机检兜底：进行、实现、予以、加以、用于、作为……角色）。章开场的定义句同理，换成动词说它管什么用（见 writing-guide「场景介绍写法」）。
    - ❌"商品资料作为核心档案，承担着为各类单据提供数据支撑的职责" ✅"商品资料是开单选商品时的数据来源"。
    - ❌"基础资料是开单时能选到什么的来源"（章开场） ✅"系统里的基础资料，决定填写单据时有哪些内容可以选择"。
17. **句式不套路**。不硬凑"不仅…还…""从…到…"，不为了排比硬凑三个一组（❌"卖什么的商品，卖给谁的客户，向谁买的供应商"，三个疑问代词是硬凑的节奏，视角还各跳各的；✅"卖的商品，买货的客户，供货的供应商"）；破折号不用，断句或用冒号。**"短句总起：展开"的修辞冒号不进章开篇**（"漏建一个商品，麻烦出在单据上：…"这类），开篇平铺直叙，冒号只留给真枚举（"五张表：商品、仓库…"）。
18. **不预告**。不写"下面我们来看看""接下来让我们了解"，直接讲。范围声明不算预告（"下面以商品资料表为例"可以写）。
19. **主语不藏**。系统做的写"系统"，读者做的用动词开头或写"你"；不写"操作将被执行""数据会被保存"这类被动腔。

## 五、密度与收尾

20. **安抚词限密**。"就行""即可""不用管""属正常"都是好词，但一个小节最多出现一次；每条 FAQ 都用定心丸收尾就是机器味。
21. **加粗只落该强调的**。场景句按步骤写法整句加粗，这是唯一例外；其余加粗落在关键词和硬警告上，不整句刷、不逐条刷。注意事项、字段表用"加粗标签+冒号"的列表是正当格式，不算滥用。
22. **收尾即停**。写完最后一条实事就结束，不写"至此…您的工作将更加顺畅""希望本文对你有帮助"式展望。
23. **废话压缩**。"具有导出能力"→"能导出"；"在…的情况下"多数时候就是"…时"；不叠限定词（"可能在部分情况下或许"），拿不准就实测，实测不了标 `[待确认]`。压缩的下限是第 3 条：压完仍要是完整句。
