# 交付前自检清单

生成后逐项过，全部通过才交用户审阅；能机检的错不留给用户。标注与脱敏的判定标准以 [walkthrough-guide.md](walkthrough-guide.md) 第五节为准，此处只列检查项。

## 两轨通用

- [ ] 骨架有据：`outline.md` 存在且末尾有 `<!-- 用户已确认 -->` 标记，正文章节与它一一对应，没有漏章也没有自作主张的增删。
- [ ] 流程走通：每个操作/配置路径在浏览器里从头到尾走通过，不是照口述或配置誊写。
- [ ] 实测来源逐节核：正文每个描述界面的小节（含没有编号步骤的描述性小节，如"查看往来情况"）都能在 notes.md 的点位清单里找到对应勾记；从配置或摘要包直出、没在浏览器里亲眼看过的段落，回走查补看后才许保留。
- [ ] 章节完整：每章有"常见问题"和"注意事项"，顺序也是常见问题在前（配置手册为"改动影响"和"注意事项"）。
- [ ] 图文一致：回看截图核对文字描述；步骤点名的按钮、字段、区域都能在图里找到（同构界面可引用前文图，正文写明）；选择、弹窗、审批面板等交互各有局部图，没有用一张表单全景代表整个填写过程。（图的有无、缺框、越界由机检覆盖，人工只核内容对不对）
- [ ] 截图与步骤所述路径一致：导航高亮落在步骤写的菜单上，不一致的重新导航重截。
- [ ] 框 ↔ 步骤文字一一对应：框的范围只含步骤文字点名的内容，图上每个框都能在步骤文字里找到含义；多框序号顺序与步骤文字一致。
- [ ] 入口可达：菜单名对不上、两图之间有跳跃、外部平台控制台这三处挂了直达链接，普通菜单路径没挂；每个链接实际点开核过落点。
- [ ] 业务数据零打码；API key、密钥、账号密码类凭证已模糊，且字段名等系统文字没被盖到。
- [ ] **格式机检通过**：`python3 scripts/render.py <文档.md>` 退出码为 0，一条告警不留。
- [ ] images/ 里没有未被引用的废图（图注格式、死链、册名、字段表列头等已由机检覆盖，不重复人工过）。
- [ ] `.orig.png` / `.grid.png` 中间产物已清理。
- [ ] 环境缺陷不入正文：按钮失效、异常引用等演示环境问题记在 notes.md 交付时报给用户，正文没有"当前工作区存在异常"式描述（内部行话已由机检覆盖）。
- [ ] 演示数据已按 demo-data.md 清理。

## 使用手册专项

- [ ] 字段写法对得上模块类型：业务流程章字段揉进步骤（必填在步骤点出且与表单一致，无字段表格）；基础资料章有三列字段表（字段 / 字段说明 / 填写说明），必填标注与表单一致。
- [ ] 无技术术语：正文无 trigger / automation / 数据触发 / config / API 等黑话。
- [ ] 术语过筛（**要逐个列出来，不能只答"看过了"**）：把正文里所有**不是界面原名**的名词抓出来列一份清单（字段表的"字段说明"列和章开篇是重灾区），逐个问"一线业务人员口头会不会这么说"；答不会的当场换白话。已知栽过的：底册、串、按仓库分行、按批次看。机检只认黑名单里的词，没见过的新词全靠这一遍。
- [ ] 后果写到业务层：扫一遍"空的/点不了/选不到"和"相关单据/涉及它的"，前者补上哪笔业务办不成，后者换成具体单据名（见 writing-guide「语言与例子」）。
- [ ] 无 AI 味：抽两章比对章开场和步骤收尾，措辞没有跨章盖章；安抚词（就行/即可）一节不超一次（陈词、子句复读已由机检覆盖，人工只核换了说法后读着自然）。对照 [user-manual-humanize.md](user-manual-humanize.md)。
- [ ] 去配置化：只写配置的表面行为，未写自动化触发条件、执行节点、审批流设计、显隐配置逻辑；计算字段公式保留。
- [ ] 自动化落地："点了之后发生什么"写进了对应位置。
- [ ] 业务流程模块册头有一张全流程图（各章开篇不配），图上表名与章节对应。

## 配置手册专项

- [ ] 第一章是成果展示（一张关键截图 + 一段话核心业务流与成果），无表清单和关系图。
- [ ] 章序即搭建顺序，只含涉及到的层。
- [ ] 每个配置单元先写"主要作用"再写内容。
- [ ] 每类配置有"入口在哪 + 编辑界面"两类截图。
- [ ] "改动会影响什么"有依据（引用查询或实测），拿不准的标了 `[待确认]`。
