# 浏览器走查规范

走查的目标是两个：拿到文档配图，拿到界面实测细节。前提是本单元的摘要包（digest.py 输出）或用户提供的流程已在手，走查是按图索骥不是瞎逛。

---

## 一、截图点位清单

动手前先从元数据推导每章的点位清单，**落盘到 `notes.md`（每章一节，逐点位一行），走完一个勾一个**。清单落盘不是仪式：它是"这章哪些界面看过、哪些没看"的唯一凭证，写作和自检都对着它核。没落盘就开截，等于点位推导没做，漏掉的点位（尤其详情页子表这类要滚到底才看得到的）事后谁也想不起来。每张主表的标准点位：

| 点位 | 截图内容 | 截法 |
|------|----------|------|
| 列表页 | 表的默认视图，含视图切换和新建按钮 | 整页，新建按钮标注 |
| 新建表单 | 点新建后的表单页，必填标记可见 | 整页或表单容器局部图；**长于一屏的分屏截，明细区必有一张** |
| 详情页 | 一条记录的详情，**含滚到底才看得到的子表页签、关联记录区** | 整页，长页面分屏截 |
| 首页/工作台 | 顶部指标和入口 + **每个跟踪页签** + **下半屏的筛选区、清单区** | 分屏截，每屏一张 |
| 每个写进手册的按钮 | ① 按钮位置 ② 点击后的弹窗/表单/结果 | ① 整页+标注框 ② 小弹窗连页面截整页，大弹窗截局部 |
| 审批入口（如有） | 提交后的审批状态展示 | 局部图 |
| 显隐字段（如有） | 触发条件满足后字段出现的样子 | 表单局部图 |

**步骤点名的元素必须落图**：写进步骤的每个"点这里、填这里、核对这里"，读者都要能在图里找到它。步骤让读者核对"已出库数量、待出库数量"，就要有一张图展示这些字段（局部图，或在结果图里标出位置）；图里找不到的，要么补图，要么别在步骤里点名。弹窗点「确定」跳到新界面的，跳转结果要有自己的图，不能停在弹窗。

**操作流程章节的图一律要框**：除了工作台、看板、大屏这类整屏都是指标图表的章节，其余章节的每一张图都要画标注框，把这一步点名的按钮、字段、区域圈出来。确认框、拦截提示这类只有一个弹窗的图也要框，框住读者接下来要点的那个按钮。机检强制，漏一张报一次。

**不许跨步骤引用图号**：正文里不写"按钮位置见图 2-12""详情页和图 3-3 一样""图 3-3 中④那排按钮"。一张图只带一套标注框，框是照着它所在那一步画的；别处引过来，框指的东西和这一步要讲的对不上，读者照着找会落空。界面同构也照截，各步骤各一张图、各画各的框，哪怕两张图来自同一个页面（讲整页构成的框住三块区域，讲某个按钮的只框那个按钮）。图号还会因为增删图而顺移，跨章引用是断链的常客。

**过程图按交互拆，一张表单全景打发不了整个填写过程**：步骤文字里让读者做选择或触发弹层的交互，各自要有局部图佐证：下拉搜索关联数据（选客户、选产品）、选中后自动带出的信息、确认弹窗、审批办理界面、右侧流程面板。这些瞬时界面在两次命令之间会关掉，用 `shot --prep` 系列参数在同一次调用里摆好再截。相邻的简单填写步骤（日期、数量、文本）才合并进一张图。

## 二、操作节奏

每一步都走「看 → 动 → 看 → 截」：

```bash
python3 scripts/browser.py goto --url <页面>
python3 scripts/browser.py snapshot                 # 确认页面对、加载完
python3 scripts/browser.py click --text "新建"
python3 scripts/browser.py snapshot                 # 确认弹出的是预期表单
python3 scripts/browser.py shot --path images/2-1-新建订单表单.png
```

- **不盲截**：每次操作后先 snapshot 看结果，页面不对就别截。
- **每次 shot 自动落一份证据文件** `<图名>.png.meta.json`：截图当时的 URL、被框元素的界面原文、页面可见按钮原文。它是机器记录，**不许手写、不许手改**——render.py 的语义审计拿它核正文里的按钮名、字段名和角标顺序，手编等于把答案抄进卷子。正文要点名的按钮务必框进对应截图，原文才会进证据；重截会自动覆盖旧证据。交付时 .meta.json 随 images/ 保留，删了机检过不了。
- **标注框只命中可见元素**（脚本强制）：隐藏容器里的残留节点（如切页后上一页的 `.ag-root`）、视口外元素自动跳过；AG Grid 底部固定统计行（`.ag-floating-bottom`）不参与框选，整表框选时数据区下边界自动收到统计行上沿。shot 会回显「框中元素」清单，回显的原文和数量跟预期对不上就是选择器命中错了，先修选择器再截。
- **确认状态用 `eval`，别读整页截图。** 每一步要确认的通常是几个离散事实：按钮是不是灰的、状态字段变了没、弹层标题是什么、拦截提示写的什么。`eval` 取 DOM 一次几十 token，读一张整页截图要两千，一册走查下来差出几十万。
  ```bash
  browser.py eval --js "(()=>{const b=[...document.querySelectorAll('button')].find(e=>e.textContent.trim()==='发货');return b?('disabled='+b.disabled):'没有这个按钮'})()"
  browser.py eval --js "(()=>{const t=[...document.querySelectorAll('*')].filter(e=>e.children.length===0&&e.textContent.includes('数据验证'));return t[0]?t[0].textContent.trim():'无拦截'})()"
  ```
- **系统文案一律用 `eval` 取原文，不要照着截图抄。** 提示语、按钮名、校验文案要一字不差写进手册，看图会把标点和空格看错。实测同一个工作区里「数据验证：退货数量不能超过库存」和「数据验证： 库存不足,无法发货」两种写法并存，冒号后差一个空格。
- **`eval` 只回答你想到要问的问题，截图会回答你没想到的问题。** 省的是同一屏的重复确认，不是下面这两种：
  - **第一次进某个页面、弹窗、抽屉，完整读一遍截图。** 按钮随状态换、条件字段冒出来、文案抄错了别处的，这类发现都来自「为别的目的截图、顺眼看到」，`eval` 问不出来。
  - **要放进手册的图，每张都要读回来看过再用。** 悬停提示入镜、下拉没关、导航高亮停在上一步、明细多出一个空行，不看就发不出来。
- SPA 内容没渲染出来用 `wait --text` / `wait --selector`，不要用截图试错。
- **小弹窗连着底层页面一起截**：确认框、提示框这类只有一两行字加两个按钮的，截整页（弹窗浮在页面上），读者能看出它是从哪个页面弹出来的；单独截一个悬空的对话框，读者认不出上下文。
- 占大半屏的抽屉、选择器弹窗、下拉面板本身内容就够多，用 `shot --selector <容器>` 截局部图，图注交代从哪打开；找容器 selector 可用 `eval` 探。
- 点击优先 `--text`（按钮文字），文字重复时 snapshot 拿编号用 `--index`。
- **要用坐标点击时，坐标从 `getBoundingClientRect` 取，不要从截图上估。** 关联字段选完值、子表加完行之后表单会撑高，按旧坐标点必然落空，然后又得截一张图找错在哪。`eval` 返回的就是 CSS 像素，可以直接喂给 `click --at`：
  ```bash
  browser.py eval --js "(()=>{const b=[...document.querySelectorAll('button')].find(e=>e.textContent.trim()==='确定');const r=b.getBoundingClientRect();return Math.round(r.x+r.width/2)+','+Math.round(r.y+r.height/2)})()"
  ```
- **控制台类 SPA（阿里云、腾讯云等）才退回「截图量位置」。** 这类页面 class 是随机哈希、元素文本也常取不到，`--text` / `--index` / `getBoundingClientRect` 都不好使，只能先 `shot` 存盘、读回来看、从图上量。
- **从截图量坐标要除以 2**：截图是 2 倍图（如 2880×1600），`click --at` 收的是 CSS 像素（1440×800）。中间再夹一个缩略图尺寸更容易算错，量完先换算再点。（`getBoundingClientRect` 拿的已经是 CSS 像素，不用除。）
- **ag-grid 子表（明细行）是 `eval` 的盲区，用截图。** 明细单元格的文本经常取不到（关联字段尤其），还会把底层列表的行混进结果。子表状态一律截图确认。
- **明细里的数字别用 `type` 输入**：ag-grid 的编辑器会吞字符（打 `9999` 只进 `99`），回车还会顺手新建一行。用 `fill --selector`，或者输入完点表单空白处提交而不是按回车。
- 截图前确认当前 URL 和页面状态，别让上一次点击的残留页面混进来；把鼠标挪到空白处再截，悬停提示（tooltip）不入图。
- **导航高亮要和步骤路径一致**：步骤写"进入仓储管理 → 商品资料"，截图里左侧导航的高亮就必须落在商品资料上。snapshot 或截图里发现高亮落在别的菜单（上一步的残留），重新从导航点一遍再截，不许用旧图凑。
- **文档里要挂的跳转链接，走查时实际点开核一遍落点**：链接打开的页面要和文字描述的一致，核过再写进文档。

## 三、每个页面都要看全

进入新页面（含弹窗、抽屉）先看全再写：**纵向翻到底，横向每个页签点开**。首屏信息量不是停止条件，翻到底才是。伙伴云的工作台、详情页普遍比一屏长，筛选区、子表页签、行内按钮常在下半屏。

**页签**：

- 先 snapshot 把页签名列全，逐个点开看过再写；页签名不等于页签内容，没点开的不写。
- 正文写到哪个页签，哪个页签就要有自己的图。页签之间布局再像也各截各的，读者是照着某一页签的说明找元素，拿到另一页签的图会对不上。
- 点页签用 `--text "<页签名>"`，点完 snapshot 确认高亮落在预期页签。

**纵向**：

```bash
# 1. 列出可滚动容器（伙伴云是嵌套滚动，scrollHeight 远大于 clientHeight 说明底下压着内容）
python3 scripts/browser.py eval --js "(()=>{const e=[...document.querySelectorAll('div')].filter(x=>x.scrollHeight>x.clientHeight+50&&x.clientHeight>300);return e.map(x=>x.className.slice(0,40)+' | '+x.clientHeight+'/'+x.scrollHeight)})()"

# 2. 全部滚到底（中段把 scrollHeight 换成 scrollHeight*0.45 等比例）
python3 scripts/browser.py eval --js "(()=>{const e=[...document.querySelectorAll('div')].filter(x=>x.scrollHeight>x.clientHeight+50&&x.clientHeight>300);e.forEach(x=>x.scrollTop=x.scrollHeight);return 1})()"
python3 scripts/browser.py shot --path <scratch>/probe-bottom.png
```

- `scroll --dy` 对伙伴云主内容区常常无效，直接用上面的 `eval` 设 `scrollTop`。
- 探查图落 scratchpad，确认有内容再重截正式配图；长页面拆两三张图入册。
- 宽度同理：子表有横向滚动条时右侧还压着关键状态列，拖到底看全再写。

## 四、截图一致性

- **窗口尺寸不用管**：驱动脚本每条命令自动把窗口铺满它所在的屏幕（换屏拖过去即可）；视口小于 1440×800 时才用 CDP 放大兜底。固定尺寸用 `HB_WIN=2560x1440 python3 scripts/browser.py start` 指定。
- 判断截图够不够大看 `eval --js "[innerWidth,innerHeight]"`，不看窗口外观。
- 不开开发者工具，同一册截图用同一尺寸。
- 同一章的截图在同一次走查里完成，避免界面前后状态不一致。

## 五、标注框与脱敏

`shot --highlight` / `--blur` 靠 CSS selector，控制台类 SPA 的随机 class 匹配不上，这时用 `scripts/annotate.py` 按百分比坐标处理。

```bash
python3 scripts/annotate.py <图> --crop 10,75 --grid              # 先量
python3 scripts/annotate.py <图> --crop 10,75 --box 14,36,73,44 --blur 10,20,45,28
```

- **位置要量不要估。** 先用 `--grid` 叠一层百分比网格读坐标，凭肉眼估比例基本每次都偏。没量过就画框脚本会直接报错拦下；`--grid` 和画框要用**同一个 `--crop`**（所有百分比相对裁剪后的成图，裁剪一变坐标全错位，脚本会拦）。
- 脚本自动把原图备份成 `<图名>.orig.png`，标错了重跑即可；交付前连同 `.grid.png`、`.grid.json` 一起清掉。**`.png.meta.json` 是截图证据，不在清理之列**，交付保留。
- **重截过的图，动手画框前先删掉它的 `.orig.png`**。annotate.py 每次运行（含 `--grid`）都从这个备份还原原图再处理，备份是旧截图的话，新截的内容会被悄悄换回去，画完框看着框位对、内容却是老的。改过界面重截的图尤其容易中招：删备份再走「量 → 画」。

**标注框**

- **框 ↔ 正文一一对应**：正文点名或重点讲解的内容都要框（步骤让读者填的字段、正文解释的区域和页签同样算），图上每个框也都要能在正文里找到含义。表单图、详情页图一样按这条办，没有免框的图种。
- **一张图不超过 4 个框**。只框正文重点解释的（默认值有讲究的、灰底填不了的、选错有后果的），填写顺序交给步骤文字，图只负责定位；框铺满整张图反而找不到重点。超上限说明这一步塞了太多事，拆步骤或拆图。
- **相邻的合成一个框**：正文一次点名好几项、它们在界面上又挨着（同一分组的几个必填字段、一排页签、一个灰底区域），框成一个大框，不打一堆小框；隔开的才分框。框的范围一字不多（说"点「订单发货」"就只贴那一个按钮，旁边的不圈；用选择器时选按钮本身，不选工具条容器）。
- **多框按操作顺序标序号**：annotate.py 多个 `--box`、browser.py 多个 `--highlight` 都按传入顺序自动标 ①②③ 角标，单框不标；含义写在步骤文字里，不写进图内。
- **标题不框**：弹窗、抽屉的标题文字不框，"是哪个窗口"由图注交代。
- **框画在目标外沿，不压内容**：框线落在按钮、字段的外面留一两像素空隙，别压住文字和组件边界（annotate.py 会自动外扩，选区仍要留余量；机检会拦）。
- **画完读回成图复核**：框贴住目标内容的实际边界，不盖空白区、不压无关的工具条和列；区域类目标（勾选区、明细区）框到内容实际结束处为止。框和角标整个落在画面内，目标贴边时先放宽截图范围再框（出界机检会拦）。框错了从 `.orig.png` 重画。

**脱敏**

- **业务数据一律不打码**：单据、客户名、号码、金额都是演示数据，是给读者核对的内容，整册零打码，不用判断真假。
- **唯一要打码的是凭证**：API key、密钥、令牌、账号密码这类（多出现在外部平台控制台），用 `--blur` 模糊。模糊只盖值，字段名、列名、按钮等系统文字保持完整清晰；打完原尺寸看一眼，系统文字被盖到就从 `.orig.png` 缩小选区重打。

## 六、演示数据

- 走查需要落数据就直接创建，标题带「演示-」前缀（如「演示-销售订单0810」）。
- 每落一条登记进 `demo-data.md`：表名、记录标题、创建入口。
- 完稿自检后统一删除：界面删除或 `hac table batch-delete-items`，删到回收站即可，不做彻底删除。

## 七、实测笔记 notes.md

每个点位走完记一条。打勾不算完成——「走过」和「验证过」是两回事，条目要把当时看到的界面原词和点击结果写下来，格式：

```
### 2-1 新建销售订单
- 页面：销售订单列表 → 新建
- 按钮原文：添加数据（右上角）、核销应收（行末操作列）
- 点击结果：点「添加数据」打开「销售订单」表单，表单右上角是「发起流程」
- 观察：保存时弹「客户不能为空」原文提示；订单编号保存后自动生成 DD20260810001；
  「优惠金额」在选了「特价订单」后才出现
- 截图：2-1-新建订单表单.png、2-2-保存校验提示.png
```

- **按钮原文**记页面实际显示的字（用 eval/snapshot 取，不凭印象）；hac 配置里的自动化名称（如「收款核销」）不等于界面按钮名（界面可能是「核销应收」），写手册只认前者实测到的原文。
- **点击结果**记点了之后系统真实发生了什么；没点过的按钮不写进正文步骤。
- 每张入册截图都要出现在某条点位的「截图」里，机检会逐张核对。

- 系统提示文案记**原文**，写手册时直接引用，不转述。
- 界面实测和 hac 配置对不上时（如配置里有的字段界面没显示），以界面为准写手册，并在笔记里标记差异，交付时向用户提一句。
- 界面异常（「字段不存在」、图表报错、按钮无反应）是演示环境缺陷：不写进手册，记进笔记，交付时逐条报给用户去修。
- 工作台/首页清单常带默认过滤（如只显示当前登录人的数据）且界面不写明：条数和主表对不上时用 `hac table list-items --columns` 按可疑字段统计核实，查实的口径写进该章注意事项。

## 八、配置类场景

文档教读者怎么配置某功能（自动化、提醒、视图、对接等）时，AI 不动手做配置，只对已搭好的演示环境做只读走查：

- 走查前先和用户确认演示环境里该配置是否已搭好；没搭好就停下来让用户搭，不代搭。
- 已搭好的：逐步进入配置入口和各级配置页，按读者第一次配置的路径截图（入口 → 配置面板各步 → 保存后的状态）。
- 可以打开新建/编辑面板截取表单形态的图，但**不保存、不提交、不改动任何已有配置**。
- 步骤文字仍按读者第一次配置的视角写（"点「新建提醒」，选择日期字段…"），图用已配好的环境截。

## 九、跨平台走查

流程涉及伙伴云以外的平台（企微、钉钉、飞书、第三方系统等）时：

- 驱动脚本直接 `goto` 外部平台，登录态同样存在持久化 profile，外部平台首次也由用户登录。
- 走查前先跟用户对齐外部平台那半段的操作路径，AI 不熟的平台不自行探索菜单，按用户给的路径走，走不通停下来问。
- 外部平台没有 hac 兜底：配置逻辑全部以用户提供 + 界面实测为准，界面看不到又问不出的标 `[待确认]`。
- **配置来源逐个走通取证**：流程里要填的每个外部平台配置项（ID、密钥、回调地址等），都要在外部平台把获取路径完整走一遍。记下获取页面的链接，从入口到值所在位置逐步截图，值本身打码或用演示值。
- 截图命名和规范不变；写作时交代清楚"现在切到了哪个平台"（如"接下来到企业微信管理后台操作"），读者要能跟上平台切换。
- 外部平台界面里的企业信息、成员名单等敏感内容同样不入图。

## 十、登录与会话

- 账号密码由用户在浏览器窗口自行输入，不代输、不存储（伙伴云和外部平台一样）。
- snapshot 看到登录页说明会话失效：停下来让用户重新登录，再继续。
