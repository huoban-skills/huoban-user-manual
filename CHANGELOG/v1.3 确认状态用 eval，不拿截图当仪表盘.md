# v1.3 确认状态用 eval，不拿截图当仪表盘

> 2026-08-30

进销存销售管理、采购管理两册连着走查，作者中途问了一句"怎么花了这么多 token"。拆下来大头不在写作，在**走查过程中读截图**：一张全页图约 2k token，两册加起来读了一百七十多次，其中大部分是"点完了吗""状态变了吗"这类确认。

病根在 `walkthrough-guide` 的「二、操作节奏」。那节写着「**不盲截**：每次操作后先 snapshot 看结果」，规则本身没错，但只管了"别乱截"，没管"用什么确认"。执行时把"确认"落成了读整页截图，而要确认的其实是几个离散事实——按钮灰不灰、状态字段变没变、提示写的什么，这些 `eval` 取 DOM 一次几十 token 就够。

同一节的坐标点击也有类似问题：原文只把 `click --at` 写给控制台类 SPA，做法是"先 shot 存盘、读回来看、从图上量"。伙伴云本身用不着这么绕，但表单选完关联字段会撑高，按旧坐标点必然落空，于是又截一张图找错在哪，一次点空要赔两张图。

本版把"用什么确认"补成明规则，并划清 `eval` 不该替代截图的边界。

## 摘要

1. 新增: 确认状态用 `eval` 不读整页截图，附两段可直接抄的 JS
2. 新增: 系统文案一律 `eval` 取原文，看图会抄错标点
3. 新增: 两条不能省的读图场景——第一次进页面要通读、进手册的图每张要看过
4. 修复: 坐标点击的默认做法改成 `getBoundingClientRect`，"截图上量"降级为控制台类 SPA 的兜底
5. 新增: 两条 ag-grid 盲区——子表状态别用 `eval`、明细数字别用 `type`

---

## 详情

### 1-2. 新增: 确认与取文案都走 eval

两段示例直接写进规范，抄了就能用：查按钮 `disabled`、抓含「数据验证」的拦截原文。

取文案这条是走查里撞出来的。手册要一字不差引用系统提示，本轮实测发现**同一个工作区里两种写法并存**：

| 出处 | 原文 |
|---|---|
| 销售发货明细 | `子表"发货明细"第1个数据的数据验证： 库存不足,无法发货` |
| 采购退货明细 | `子表"采购退货明细"第1个数据的数据验证：退货数量不能超过库存` |

冒号后差一个空格。这种差异看图基本抄不对，`eval` 拿回来的是字符串，不会有歧义。

### 3. 新增: 划清边界，不是全面砍读图

**`eval` 只回答你想到要问的问题，截图会回答你没想到的问题。** 本轮几个最有价值的发现都来自"为别的目的截图、顺眼看到"：

- 报价单的行内按钮随状态换（审批中是「通过」「驳回」，通过后同一位置变「转正式订单」）
- 发货方式选「快递」后表单下方冒出「快递单号」，选「货运」冒出「车牌号」
- 付款单顶部的「填写说明」写的是收款侧的话，是从收款单抄来没改的

这三条没有一条是"我想到要去查"的，`eval` 问不出来。所以规范里把两种场景明确排除在节流之外：

- **第一次进某个页面、弹窗、抽屉，完整读一遍截图。**
- **要放进手册的图，每张都要读回来看过再用。** 悬停提示入镜、下拉没关、导航高亮停在上一步、明细多出一个空行，这些本轮都发生过，不看就发不出来。

省的是**同一屏的重复确认**，不是第一次的通读，也不是成图复核。

### 4. 修复: 坐标从 rect 取，不从图上估

原文把"截图上量位置"写成了坐标点击的通用做法。改成两层：默认 `eval` 拿 `getBoundingClientRect` 中心点（返回值就是 CSS 像素，可以直接喂给 `click --at`）；只有控制台类 SPA 那种 class 随机哈希、文本也取不到的页面，才退回截图量。

顺带把「坐标要除以 2」限定到"从截图量"的情形，并注明 rect 拿的已经是 CSS 像素，不用除——原文没区分，容易照着除两次。

### 5. 新增: 两条 ag-grid 盲区

这两条是反例验证出来的，不是推想的。第五章填采购退货明细时，先按新规则用 `eval` 读子表，连试几次都不对：

- 关联字段（退货产品、退货仓库）的单元格文本取不到，返回空
- 选择器会把底层采购订单列表的行一起捞进来，两套行混在一个结果里

在这上面来回试的开销超过了直接截一张图。所以规范里写死：**子表状态一律截图确认**。

同一处还撞上输入问题：明细数字用 `type` 输入，打 `9999` 只进 `99`（编辑器吞字符），回车还会顺手新建一行，导致明细多出一条空行。改用 `fill --selector`，或者输入完点表单空白处提交而不是按回车。

## 验证

| 用例 | 预期 | 结果 |
|---|---|---|
| 采购管理第五至七章按新规则走查 | 不再出现坐标点空 | 0 次（销售册同类操作曾出现 8~9 次） |
| 拦截提示原文取用 | 标点空格与界面一致 | 两处差异均正确取回，见上表 |
| ag-grid 子表用 `eval` 读单元格 | 失败，回退截图 | 失败 3 次后改截图，规则据此写死 |
| 走查完整性 | 章节点位不因节流而遗漏 | 采购七章 45 张图，`render.py` 格式机检除标注框外零报 |

**没做精确 token 计量。** 本版只能说明省在哪一类调用上，省了多少倍没有实测数字，不写进规范。下一册走查若要量化，需要在 `browser.py` 侧加调用计数，本版未做。

## 已知未覆盖

- `eval` 的选择器写法目前靠现场拼，没有沉淀成 `browser.py` 子命令。高频的三种（查按钮 disabled、取拦截原文、拿元素中心点）值得做成 `browser.py assert` / `text` / `locate`，本版只写进文档没进脚本。
- 标注框仍然要"先叠网格再量"。走查时已经拿到过元素 rect，理论上能直接换算成百分比省掉量的一步，但区域类框（一组字段、一整块卡片）没有单一 DOM 节点对应，这条路只对单元素框成立，未纳入本版。
