# v1.6 走查省着看：snapshot 只报变化，读回分级

> 2026-08-31

v1.5 的语义审计本身跑在 Python 层不花 token，但顺着"哪里在烧 token"盘了一遍走查流程，发现两个老习惯才是大头：snapshot 每次把整页文字全量重打（左侧导航、顶栏这些框架内容页页相同，一册走查跑上百次，重复部分就是几万 token）；入册图每张读回、重截也重读（v1.5 之后框的有无、出界、角标顺序已由机检接管，只改框的重截读回价值归零）。

## 摘要

1. 新增: `snapshot` 默认只输出与上次的差异，`--full` 全量。页面文本按行比对省略相同行；可交互元素按编号逐位比对，连续相同的折叠成 `[0]~[17]（与上次相同）`——编号是真实编号，`click --index` 照常用。状态存 profile 目录 `snapshot-last.json`，多实例互不干扰
2. 变更: 读回分级（walkthrough-guide）——只改标注框、页面没重新操作过的重截免读回，看 shot 回显的「框中元素」清单即可；首次进页面、内容有变的截图照旧读回；annotate.py 画的框机检不掌握原文，照旧读回
3. 新增: `render.py` 报错折叠——同一模板（去行号和「」内容）的报错达 8 条只打前 5 条 + 汇总行，修复方式相同的报错看 5 条和看 30 条信息量一样
4. 新增: 写作时查按钮原词先 `grep images/*.meta.json`（SKILL.md 阶段三），不回浏览器再走一趟

## 验证

| 用例 | 预期 | 结果 |
|---|---|---|
| 连续两次 snapshot，导航相同、内容区换页 | 相同行省略、元素折叠成区间、新元素带真实编号 | 符合 |
| 同一页面连续两次 | 输出「与上次完全相同」 | 符合 |
| 首次 / `--full` | 全量输出 | 符合 |
| 12 条同模板报错 + 1 条其他 | 前 5 条 + 汇总 + 其他 1 条 | 符合 |
| v1.5 全套 fixture | 不回归，退出码 0 | 通过 |

## 已知未覆盖

- 文本按"行内容"去重：内容区某行恰好与导航某行同字时会被误省，`--full` 兜底，实际页面里罕见。
- 报错折叠对"每条要单独处理"的类别（如多个不同的 hac 内部名）同样生效，被折叠的下轮重跑仍会报出，不会漏。
