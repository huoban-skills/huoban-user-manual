# v1.4 册头流程图漏没漏，机检说了算

> 2026-08-30

采购管理册交付前作者看 HTML 预览，发现册头的全流程图是一坨等宽字符方框，跟销售册那张 SVG 完全不是一个东西。查下来是执行时跳了 `flow.py`：`SKILL.md` 写着"业务流程模块动笔前先出册头总览流程图：从骨架写 flow.json，`flow.py` 渲染"，骨架 `outline.md` 里也自己写了「模块类型：业务流程型（册头配一张全流程图）」，正文却直接在围栏代码块里敲了张 ASCII 图。

**跑完机检零报。** 这才是要紧的地方——ASCII 图不是图片，图号、图注、标注框那一整套检查全部绕过去了，正文其余部分又都合规，于是"机检通过"给了个假的绿灯。同一个漏法在这套流程里已经不是第一次：规范写在 SKILL.md 的执行步骤里，但机检不查，执行时漏掉就没人拦。

本版把这条补进 `render.py`。

## 摘要

1. 新增: 正文出现围栏代码块即报错，指向 `flow.py`
2. 新增: `outline.md` 声明「业务流程型」但册头没有 SVG 总览图即报错
3. 修复: 第 2 条初版用整篇子串搜「业务流程」，误伤基础资料册

## 详情

### 1. 新增: 正文不许有围栏代码块

手册读者是业务操作者，正文没有代码块的正当用途。三本存量手册（基础资料、销售管理、采购管理定稿）实测围栏代码块数量都是 0，规则零误伤。

报错信息直接给出路：册头全流程图用 `flow.py` 出 SVG，短流程用文本箭头 `→` 写进正文——后者是 `SKILL.md`「输出物结构」里本来就有的规定，这次在报错里复述一遍，省得读者再翻。

这条拦的是"画了，但画错了形式"。

### 2. 新增: 业务流程册必须有册头总览图

拦的是另一种漏法："根本没画"。判据取 `outline.md` 的「模块类型」，这是骨架的固定字段，两种取值：

| outline.md 写法 | 册头 SVG | 结论 |
|---|---|---|
| 模块类型：业务流程型 | 有 | 通过 |
| 模块类型：业务流程型 | 无 | 报错 |
| 模块类型：基础资料型 | 无 | 通过（基础资料册本来就不配流程图） |

`check()` 里新增 `head_svg` 标志，在第一章之前遇到 `.svg` 图片时置位；函数收尾时读同目录 `outline.md` 判定。

**为什么不做成"所有手册都要有总览图"**：基础资料型模块的骨架里明写着"不配全流程图，固定含「基础资料导入说明」章"，一刀切会把基础资料册全部判错。

### 3. 修复: 初版的子串误伤

第 2 条第一版写成 `if "业务流程" in outline_全文`，跑回归时基础资料册当场报错。原因是它的排除表里有一行：

```
| 全部业务单据 | 归各业务流程册 |
```

「归各业务流程册」里含「业务流程」四个字，被整篇子串搜命中。改成只取「模块类型：」那一行的值再判断：

```python
_m = re.search(r"^\s*[-*]?\s*模块类型[：:]\s*(.+)$", _o, re.M)
if _m and "业务流程" in _m.group(1):
```

**这次误伤是回归跑出来的，不是想出来的。** 新加的机检必须拿全部存量稿子回归一遍，只在触发用例上验过等于没验——v1.2 的「用于」也是这么发现的，同一个教训第二次遇到。
