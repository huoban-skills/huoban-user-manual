# v1.5 界面原词跟证据走，换 agent 不滑坡

> 2026-08-31

财务管理册（进销存 v1.6.0）复盘暴露的核心问题：文字复查、图片复查、格式机检全部走完，第 2.1 节仍写着「点『创建』」「列表右侧可查看收款详情、收款核销、收款审批」——而截图和实时页面显示的是「添加数据」「核销应收」。换 codex 执行时这类错误更密集。

根因不是缺规则，是规则压在"agent 自觉"上：界面原词、框与正文对应、"已走查"都靠 agent 读规范并全程记住，勾选清单勾了不等于查了。三个具体漏洞：

1. `vocab.py` 把 hac 自动化里的内部按钮名（「收款核销」）混进界面词表，机检拿错误答案批卷；
2. 「创建」「添加数据」都在平台自带词白名单里全局放行，写错也过检；
3. 截图里的界面文字没有任何机器可读的留底，图文语义比对无从做起。

本版把关键原则从"文字规则"改成"结构化证据 + 自动检查 + 不通过不交付"。判断标尺：每条关键规则，问"agent 完全没读这条时，脚本拦不拦得住"。

## 摘要

1. 新增: `browser.py shot` 自动落截图证据 `<图>.png.meta.json`（URL、被框元素原文、页面可见按钮原文），机器记录、禁止手编
2. 新增: 标注框只命中可见元素；排除切页残留的隐藏节点和 AG Grid 底部统计行（`.ag-floating-bottom`），整表框选时数据区下边界自动收到统计行上沿；shot 回显框中元素清单
3. 变更: `vocab.py` 自动化名称从 `options` 移出，单独落 `hac_names` 层，只用于拦截、不算界面词
4. 新增: `render.py` 截图证据语义审计（并入现有机检，不另开命令）：
   - 正文引用的每张 PNG 必须有 `.meta.json` 证据，没有就报"重截"
   - 点击语境的「X」在 `hac_names` 里、又不在任何界面证据里 → 硬报错（拦「收款核销」冒充「核销应收」）
   - 点「X」在证据层可用时必须有截图证据背书（拦凭常见页面模式脑补的按钮）
   - 新增类按钮（创建/添加数据/新建/创建新数据）按小节核对本节证据，界面是「添加数据」就不许写「创建」
   - 图上框住的元素原文必须在本节正文出现（框↔正文一一对应）
   - 多框角标顺序必须与正文提及顺序一致（拦①②与操作顺序相反）
   - notes.md 点位清单必须记到每张入册截图，缺的合并成一条报出
5. 变更: `walkthrough-guide.md` 点位条目结构化——按钮原文、点击结果必填，打勾不算完成；`.meta.json` 交付保留
6. 变更: `SKILL.md` 新增"事实来源分级（硬规则）"：界面词只认浏览器实测，hac 名称是内部配置名；机检退出码非 0 不许宣布完成
7. 变更: `self-check.md` 已被机检接管的项收窄为"人工只核机器核不了的部分"

## 详情

### 证据由工具生成，不由 agent 手写

复盘文档原方案是让 agent 逐步骤手写 evidence.yaml——这本身又是一条靠自觉的规则，弱 agent 会凭想象把 yaml 填得很漂亮，审计拿编造的证据核对正文等于没审。本版改为证据是 `shot` 的副产品：agent 截图（本来就必须截），证据就自动存在；机器记录的界面原文和 agent 写的正文来源独立，才核得动。

### 门禁只有一个入口

语义审计没有做成独立脚本，全部并进 `render.py`——agent 已有"写完跑 render"的肌肉记忆，新检查挂在必经之路上。交付阻断不靠状态机文件，靠"机检不过 = 退出码 2"这个物理事实。

### 词表分层是「收款核销」问题的正解

hac 自动化名称与界面按钮名用途相关但事实层级不同：前者用于理解配置，后者才能写进手册。`vocab.json` 的 `hac_names` 层专职当"错误答案对照表"：正文点击语境命中它、界面证据里又没有 → 报错并提示"配置名≠按钮名"。若界面确实显示该词，把它框进截图即可通过——报错的出路是补证据，不是放行。

## 已知未覆盖

- 测试三（AG Grid 排除）只做了代码实现，未在真实浏览器会话里回归，下次走查时顺手验证。

- 证据只覆盖 `shot` 之后的世界；`annotate.py` 补画的框没有元素原文，角标顺序审计对它不生效（控制台类 SPA 场景）。
